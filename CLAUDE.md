# CLAUDE.md

The ROS 2 package `syncai_driver_manager`, written in Rust (`rclrs` 0.8): a UDP bridge between ROS 2
and the quadruped robot's low-level controller (gait controller). It is a port of
`~/SyncAI-Robot-Workspace/src/syncai_driver_manager` (C++ / rclcpp), and **its external interface
must stay identical to the C++ version** (node name, executable name, parameter names, topics,
message types, QoS, service names): `syncai_robot_state` and `syncai_backend` both depend on it.
When behaviour is in doubt, the C++ version is authoritative. Deliberate exceptions: the added
`safety_locked` topic, and `set_safety_lock` (`std_srvs/SetBool`), which replaces `reset_safety`.

**The repo root is the package itself** (`package.xml` and `Cargo.toml` are at the root); the
Workspace pulls it into `src/syncai_driver_manager` with vcstool (replacing the C++ version).
`interface.repos` and `.devcontainer/` (including the Dockerfile) are only for developing this repo
on its own; the Workspace has its own image and does not use them. There is no Makefile or
docker-compose.

## Build and test

Everything runs in the Dev Container `syncai-ros2-rust` (VS Code Reopen in Container, or
`devcontainer up --workspace-folder .`). The container's workspace root `/workspace` is the named
volume `syncai-ros2-rust_workspace` (holding build / install / log and the `src/syncai_common` that
`postCreateCommand` vcs-imports), and this repo is mounted at `/workspace/src/syncai_driver_manager`.
The host has no ROS / cargo, and no build output ends up in the host's repo directory.

```bash
docker exec syncai-ros2-rust bash -lc 'cd /workspace && colcon build --symlink-install --packages-select syncai_driver_manager'
docker exec syncai-ros2-rust bash -lc 'cd /workspace/src/syncai_driver_manager && cargo fmt --check'
docker exec syncai-ros2-rust bash -lc 'cd /workspace/src/syncai_driver_manager && cargo clippy --target-dir /workspace/build/.clippy --all-targets'
docker exec syncai-ros2-rust bash -lc 'cd /workspace/src/syncai_driver_manager && cargo test --target-dir /workspace/build/.clippy'
```

- `cargo` commands need one `colcon build` first: `/workspace/.cargo/config.toml` is generated by
  colcon-ros-cargo.
- If `syncai_common` is missing (a fresh volume), run
  `cd /workspace && vcs import < src/syncai_driver_manager/interface.repos` in the container.
- Warnings from `/opt/ros2_rust_underlay/...` (rclrs itself) are not ours; ignore them.
- Before finishing, build / clippy / fmt must have zero warnings and all unit tests must pass.

## Real-robot safety (important)

- This machine is connected to the real robot: the controller is at `192.168.1.120:50051`, and
  telemetry is sent to `192.168.1.103:50010`. Other containers such as `robot01` are running ROS
  next to it (domain 1).
- When testing, **never send commands to `192.168.1.120`** (cmd_vel / set_motion_key make the robot
  move). Use loopback: `-p telemetry_recv_ip:=127.0.0.1 -p command_target_ip:=127.0.0.1`, change
  the ports, and `export ROS_DOMAIN_ID=77` (not 1 or 2).
- Only *listening* on 50010 to check whether the controller is sending telemetry is safe, but only
  one program can bind it at a time.

## Architecture (`src/driver_manager_node/`)

| File | Responsibility |
| --- | --- |
| `mod.rs` | Wiring: parameters → two UDP sockets → workers / services / telemetry thread |
| `protocol.rs` | **Pure functions** for packet <-> struct; no sockets / Node / ROS message types; all unit tests live here |
| `parameters.rs` | Velocity gains (`MandatoryParameter`, >= 0), UDP addresses (`ReadOnlyParameter`) |
| `session.rs` | UDP sockets (telemetry `listen`, command `connect`) |
| `command.rs` | `CommandLink` (sends ASCII commands), `SafetyLock` (no trigger condition yet) |
| `telemetry.rs` | `std::thread` that receives packets, parses them and publishes ROS messages |
| `publishers.rs` / `subscriber.rs` / `service.rs` | ROS interfaces |

Threads: `cmd_vel` has one rclrs Worker, and the four services share one Worker (equivalent to the
C++ version's two MutuallyExclusive callback groups; the two workers run in parallel). Telemetry has
its own `std::thread`. New packet parsing logic goes in `protocol.rs`, with unit tests.

## rclrs pitfalls (all hit in practice)

- **Params YAML keys do not expand wildcards**: only `/**` or the node's full name match.
  `/**/driver_manager` is silently ignored and everything falls back to defaults. This package's
  YAML uses `/**:`.
- **Worker = callback group**: callbacks from `node.create_*` all queue on the executor's single
  thread; callbacks from `worker.create_*` run on that worker's own thread. The callback shape is
  `FnMut(&mut Payload, Msg)`.
- **No SIGINT handler**: Ctrl-C ends the process immediately and `Drop` does not run.
  A process backgrounded with `&` in a non-interactive shell script ignores SIGINT; send SIGTERM to
  stop it.
- **`ros-env` versions**: the package uses `ros-env` 0.2 while rclrs uses 0.3 internally, and their
  message types are incompatible. Do not use rclrs helpers that return message types (e.g.
  `Time::to_ros_msg`); build them yourself from `Time::nsec`.
- The `Message` trait under `rclrs::*` is `rosidl_runtime_rs::Message`.
- Message packages do not go in `Cargo.toml` but in `<depend>` in `package.xml`; without it
  `ros_env::<pkg>` does not exist.
- `launch/` and `params/` are installed to share via `[package.metadata.ros] install_to_share` in
  `Cargo.toml`.

## Conventions

- Everything is written in English: code and config comments (Rust, Cargo.toml, Dockerfile,
  devcontainer.json, toml…), log messages, and docs such as README / CLAUDE.md. Log messages carry a
  `[Module]` prefix (e.g. `[Telemetry]`, `[DriverManagerNode]`).
- Formatting follows the root `rustfmt.toml` (max_width 100); Cargo.toml enables
  `unsafe_code = "forbid"` and `clippy::all`.
- Commits use Conventional Commits (`.github/prompt/copilot-commit-message-instructions.md`), in
  English.
- `syncai_common` is another repo that vcstool pulls into the container workspace (it is not in this
  repo); change message definitions in SyncAI-Robot-Interface.
- Known open questions (left as TODOs in the source; need the real robot): the sign of `angular.z`,
  IMU_RPY units, joint order, and the safety trigger conditions (battery < 20%, JOINT_TEMP
  overheating).
